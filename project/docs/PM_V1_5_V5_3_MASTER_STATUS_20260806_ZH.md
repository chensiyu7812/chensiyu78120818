## V5.2的根本问题：不是某个组件的bug，是生成器根本看不到证据原文

`compose_locked_response()`是确定性字符串拼接——LLM从来没有真正看到MS/ME的证据文本，只是
把模板片段拼在一起。这意味着V5.2时代做的任何"MP/MS/ME候选质量"评估，都测不出"生成器会不会
正确使用这个证据"这个问题，因为生成器根本不参与证据使用这一步。V5.3的typed response program
（生成器看到完整typed证据，产出一次整合过的回复，配一层guard+rewrite+兜底的安全网）是专门
针对这个根本问题设计的，本报告里几乎所有"V5.3新发现的bug"，都是这个新架构第一次让"生成器
怎么用证据"这件事变得可测试、可观察之后才发现的——V5.2不是没有这些问题，是V5.2的架构让这些
问题不可见。

## 七、所有组件共同的一个已知缺口：judge没有别名映射——**已修复**

Step1的MS试点里发现：EvoEmo的证据文本习惯用第三人称叙事（比如把用户叫"Anna"），生成器
拿到了`current_user_known_aliases`能正确把"Anna"解析回"you"，但risk judge没有拿到同样的
映射，会把这种**正确的**指代解析误判成`unsupported_personal_claim`违规。这个问题在MP/MS
试点里都出现过。用户明确要求一并修正后，给`v1_5_mvp_judge.py`的两个message builder加了
一个纯新增、默认关闭的`current_user_known_aliases`参数（不传=跟修复前完全一样的prompt，
已认证的正式Step1 judge管线不受影响），并接进了MP/MS/RS/ME全部四个Step1试点脚本。9个
既有测试全过（未改变默认行为），加了2个新测试验证新参数行为。

## 九、泛化问题的真实探索：用错了代表层，已确认；根治方案已有明确路线图

用户明确追问"内部训练的PM能不能公平泛化到外部"，担心"如果不能，之前的工作是不是白做了"。
真实探索过程和结论如下：

**第一步，直接查训练数据本身**：468个内部合成训练用户，**每一个**MP/MS/ME都恰好2条，
零方差；session跨度只有3-11。这不是猜测，是直接读`memory_backend.jsonl`数出来的。

**第二步，用项目已有的零API OOD审计工具（`41_diagnose_merged_ood_audit_v1_5.py`）真实跑**：
EvoEmo真实state在`PMV2FeatureBuilder`下**100%被判定严重metadata OOD**（语义特征完全没问题，
0%严重语义OOD——问题只在count/age这类目录规模统计上）。

**第三步，做了一次假设检验**（新脚本`56_diagnose_catalog_diversity_ood_hypothesis_v1_5.py`）：
把训练数据的count/age按EvoEmo真实分布重新采样，看能不能把这100%降下来。过程中先后发现并
修复了自己的一个真实bug（`step0_observation`被缓存、扰动一开始完全没生效），修复后的真实
结果是：**即使真的把count/age范围补齐，EvoEmo的10个真实state依然100%严重OOD，没有改善**。

**第四步（关键修正，来自另一个Codex的审核，核实后确认成立）**：`PMV2FeatureBuilder`的
docstring原话——"strictly pre-retrieval...never reads actual memory snippets, retrieved
IDs, item-level top scores"——**它根本不是V5.3计划要用的代表层**。查
`PM_V1_5_V5_3_INTEGRATED_EVIDENCE_EXECUTION_PLAN_20260805_ZH.md`（写于8月5日，早于这次
session）第2.1-2.3节，V5.3的正式计划早就规定了candidate级接口："Top-k发现，Top-1执行"，
每个组件一张`contribution slot`表（MP/MS/ME/RS各自"值得开启所需的可观察槽位"）。**这次
OOD探索全程测的是一个V5.3计划里已经要被取代的旧表示，不是实际要用的东西**——第三步"即使
补齐范围也没用"这个负结果，反而印证了"别再在这条路上投入"是对的判断，不是说明泛化问题
无解，是说明这条路本来就不是正确的检验对象。

**结论**：
1. `PMV2FeatureBuilder`及其OOD诊断正式**降级为历史诊断，不再作为V5.3的Step1最终primary
   代表层**——这不是新决定，是把V5.3计划里本来就写好、但这次探索之前没意识到要遵守的
