# PM V1.5 MP/MS/ME 连续失败的根因结论

状态：`ROOT CAUSE FROZEN / BEFORE EXTERNAL QUALIFICATION`

## 结论

这不是三个组件轮流“通过又失败”，而是以前把不同层的证据用同一句“通过”表达。当前能被
证据支持的结论是：

| 组件 | Step1内部构念 | 外部表示运输 | 外部路由行为 | Step2给定资源后的执行 | 根因 |
|---|---|---|---|---|---|
| MP | V1.5b内部门通过 | 数值覆盖1.00 | 114个候选开109个，非准确率 | 2/8 | preference/profile子类型错位；外部只见Education/Job且多为无关或不增量；单回复偏好不可证伪 |
| MS | V1.5b内部门通过 | 数值覆盖.951 | 204个状态只开4个，非准确率 | 6/8 | 候选形态最接近，但外部head过保守；强制提供时generator常能执行，尚不能证明PM会选时机 |
| ME | 历史上标为晋级，现因gold错绑失效 | 数值覆盖1.00 | 198个eligible状态开198个，非准确率 | 3/10 | 内部假设可复用结果，外部是任意过去episode；标签未绑定实际rank-1；generator又被迫使用无结果事件 |

因此，主要根因按优先级是：

1. **训练题与外部考题的候选语义不一致**，而不只是主题或词面分布不同；
2. **标签没有绑定实际执行候选**，模型学会的是构造条件，不是“这条记忆值不值得用”；
3. **同一个source名称包含不同subtype和功能**，数值落入训练范围却不等于功能同构；
4. **多组件合同可能互斥**，机械16动作组合会制造无解的Step2题；
5. **generator的出处短语只证明表面时态，不证明证据槽绑定正确**。

BAAI不是这里的主解。它最多改善语义相似排序，不能判断一段过去事件是否包含可复用结果、
profile是否真正增量、旧原因能否迁移到现在，也不能修复错误gold或互斥执行合同。

## 为什么ME本应最容易却反而暴露问题

“某个具体event”只有在以下链条成立时才容易：过去事件属于同一用户，事件完整，当前目标相似，
其中包含具体动作/选择和可观察结果，当前没有重复说明，且把它作为试探性选项不会越界。旧内部
数据直接把这条链条写进了正例条件；EvoEmo compiler则把任意过去seeker episode都叫ME。
二者只共享字段名，不共享可用性定义。

更严重的是，旧V3确认集中8个ME正例的实际Top-3都是重复的“routine week”同主题句。标签说
“有相关、非冗余事件”，模型看到并执行的候选却不是那条事件。于是漂亮内部指标不能回答真正
问题。这个结论不是“ME资源永远没用”，而是旧ME训练资格无效，必须在正确单位上重建。

## “学习”与“考卷”应如何同构

内部数据不复制EvoEmo内容，也不读取p7–p18答案；需要覆盖的是外部候选的语义轴：

- candidate subtype；
- 是否含动作、结果或机制；
- 当前goal fit，而非只有topic相似；
- 是否被当前消息重复；
- 时间陈旧、冲突和实体/角色一致性；
- 当前请求、负担和其他资源的兼容性。

内部训练必须包含与外部形态一致的正负例：同主题但无结果、未解决负面事件、错目标、错实体、
当前已重复、陈旧冲突、一般生活细节，以及真正包含可复用结果的事件。必须先让冻结检索器选出
exact rank-1，再给这条候选标机会；不能先按场景设计label，再默认检索器找到了设计中的证据。

## 各组件一次性修复边界

### MP

保持一个MP bit，但分别记录`MP_PREFERENCE`与`MP_PROFILE`。偏好要用相反偏好同状态配对验证；
profile只有在与当前目标/实体有关、当前未明说且能改变回答时为on。Job/Education等一般事实多数
应成为负例，而不是因为存在就开启。

### MS

目标定义为“过去会话主线/区分是否能帮助承接当前目标”。内部补全外部形态的同主题硬负例，
确认head能在新用户上同时on/off。`6/8`只保留为给定资源后的执行证据，不拿来晋级外部路由。

### ME

不增加动作bit，但candidate typed为`REUSABLE_OUTCOME / CONTEXT_EVENT / UNRESOLVED_EVENT`。
V1.5的ME-on只接受exact rank-1中存在“过去动作或选择 + 可核验结果/机制”、当前goal相似、非冗余
且可安全类比的`REUSABLE_OUTCOME`。纯背景或未解决事件默认off；连续性背景交给MS。

### 联合动作与Step2

保留16个合法动作，但增加outcome-blind joint feasibility：若低负担RS禁止第二动作而ME要求追加
选项，按边界/风险优先关闭冲突bit并记录requested、feasible、realized三种动作。Step2验证必须
绑定`component -> exact selected evidence -> allowed function`；固定“Last time/In the past”短语
不能再单独算执行成功。

## 重建后的最小资格门

1. 静态门：每个label与实际rank-1 id/text一致；Top-k去重；无condition/background快捷标签；
2. 内部门：user-grouped OOF、condition holdout、fresh主题确认同时报告BA、recall、specificity、
   Brier gain、on/off比例；
3. 语义运输门：除数值范围外，分别报告subtype与exact-rank1机会覆盖；
4. Step2门：选中证据绑定、真正做功、material misuse分开；联合合同冲突样本不进入能力分母；
5. 仅在上述冻结后消费EvoEmo p7–p12；p13–p18仍是最终lockbox，外部结果不得回流调模型。

当前16条包永久保留为开发失败证据。下一步不是补第三评审、扩大同机制样本或换BAAI，而是先修
candidate-gold绑定与MP/ME ontology，再用全新、内容不重叠的内部资格集验证。只有这样才能证明
PM学的是换一批用户记忆后仍可用的“是否注入能力”，而不是记住内部微型世界。
